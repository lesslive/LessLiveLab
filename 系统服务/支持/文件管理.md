## 定义

资产是经本人消化处理、能明确服务某个模块的 Markdown 文档，包括想法、认识、判断、经验、策略、行动安排与实践成果。
## 原则
本仓库依据 DDD、YAGNI、SSOT 原则，规定文档的准入、存放、生产与维护方式。
## 准入

- 公共知识、文章摘录、PDF、聊天原文等原始资料不入库，加工为个人文档后入库
- 本仓库派生的图片、视频、代码工程等文件不作为资产入库，在其生产工具中管理
- 本仓库必须要使用的图片视频等附件，在系统服务/附件里统一管理，但应保持克制

## 分类

归属、用途和模块职责是不同维度，不能互相替代。文档是否位于某个目录，不单独决定它是否对外发布。

### 按归属

- **用户资产**：仓库用户创建和维护的文档。
- **官方资产**：仓库内置的模型和示范文档。

### 按用途

- **素材**：资产可作为对外输出的素材，不代表该文档本身需要或适合公开。
- **产品**：面向受众交付的完整成果，如书稿、训练营课件、视频课脚本等。产品内容应有自身完整结构，不能以链接到仓库素材代替交付正文。
- **表达作品**：用于与受众沟通、互动的对外内容，如文章、推文、进展汇报、活动邀请和使用说明。故事是表达作品的一种，不以是否存放在名为“故事”的目录中判定。

## 维护

- 新增内容根据职责存放于对应课题的具体模块；
- 可暂存在根目录，应及时处理归位或删除。
- 一个文件夹承载一个主题，内部文件围绕主题派生。
- 与文件夹同名的文档是文件夹笔记，承载该主题的原生内容，并为内部文件提供索引。
- 同一资产只维护一份正文，不保留版本副本，历史由 Git 管理。
- frontmatter 按最小化原则编写。新增字段和标签须能说明：缺少它们会造成什么问题。

## 创作

素材作为表达作品的来源时：
- 不把来源文档直接当作表达作品。
- 以 callout 说明来源、背景与上下文，并链接来源文档；发布时排除。
- 事实只在来源处维护。已发布的表达作品不随来源修改；来源变化时，新增派生作品。
- 在主题文件夹笔记中记录发布地址。独立表达作品可按单一事实来源原则保留正文或仅保留发布链接；同一作品不在仓库多处重复维护。
- 产品发布后仍在服务模块的产品目录中保留完整主稿，并在文件夹笔记中记录发布地址或版本信息；后续迭代不得让仓库失去可交付的完整正文。

示例：

```
项目/
├── 价值/某主题/
│   └── 某主题.md（观点作品或索引）
├── 进度/某阶段/
│   └── 某阶段.md（进展作品或索引）
└── 服务/
    ├── 某活动/
    │   └── 某活动.md（参与信息或服务作品）
    └── 训练营/
        └── 训练营.md（完整课件与索引）
```

## 说明

- **未规定即由用户决定**：本规范只规定资产本身，未规定的事项由用户自行决定。选题设计、任务执行、主题选择等属于相应模块，不在此规定；已在其他文档定义或由工具本身提供的规则，不在此重复。
- **以 Markdown 表达为先**：流程、关系、进度与对比，可用 Mermaid、看板、表格与 callout 表达。不禁止但也不鼓励使用图片等形式作为仓库资产，增加 AI 阅读成本、也不方便 git 逐行比较 diff。
- **文档干净优先于管理便利**：frontmatter 与标签每次打开文档都会被读到，只有在查询时才有用。宁可降低管理便利，也不让文档被无用的字段和标签干扰。
- **字段与标签同等审慎**：新增字段或标签适用同一判定，不存在"字段不能加就改用标签"的替代关系。信息可以由正文、目录、文件名或链接承载。
